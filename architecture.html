Data Flow

Server components read the repository directly; client components mutate through server actions in lib/actions/. There is no client-side data store.

Domain Model

Category

  • id, name, slug (unique)
  • icon (refrigerator | tv | fan | etc.)
  • description, sortOrder

Product

  • id, name, slug (unique)
  • categoryId, brand, model
  • price (BDT), description
  • images: {url, publicId}
  • specs: {label, value}[]
  • availability, published, featured
  • createdAt (ISO)

Business Rules

  • Slugs must be unique for products and categories
  • Category can't be deleted if products reference it
  • Only published products appear on storefront
  • featured products show on home page's Featured section

Authentication Flow

1. Request to /admin/* No session cookie found
2. proxy.ts intercepts Redirects to /login?next=/admin/...
3. Staff signs in POST to server action, verifies ADMIN_USERNAME + ADMIN_PASSWORD
4. HMAC-signed cookie created Session expires in 7 days
5. Redirect to admin route app/admin/layout.tsx calls requireAdmin() to verify
6. Server actions re-check session Defense in depth — every action calls getSession()

Server Actions Pattern

Action Structure

  • Call getSession() first, return { ok: false, error } on failure
  • Validate input (client + server-side)
  • Call repository method
  • updateTag(CATALOG_TAG) to invalidate cache
  • Admin pages call router.refresh() after mutations

Server actions are the only way the UI mutates data. They are the swap point for Supabase/Mongo: the UI calls these, not a client.

Data Layer Contract

CatalogRepository Interface

Reads:
  • listCategories(), getCategoryBySlug(), getCategoryById()
  • listProducts(), listPublishedProducts()
  • getProductById(), getPublishedProductBySlug()
Writes:
  • createProduct(), updateProduct(), patchProduct(), deleteProduct()
  • createCategory(), updateCategory(), deleteCategory()
  • resetDemoData() (prototype only)

Current Implementation: MongoDB + Mongoose

  • Collections: categories, products
  • String _ids (seed categories: cat-*, products: UUID)
  • Products have images[] and specs[] embedded arrays
  • slug has unique index on both collections
  • createdAt/updatedAt from Mongoose timestamps

Caching Strategy

Cache Annotations

  • 'use cache' on reads
  • cacheLife('hours') for TTL
  • cacheTag(CATALOG_TAG) for invalidation
  • updateTag(CATALOG_TAG) after writes

Storefront pages are partially prerendered (static shell + streamed dynamic holes). Runtime data must sit inside <Suspense> (see loading.tsx under products).

Conventions

  • Split UI into small components — Pages compose them
  • Semantic design tokens only — bg-background, text-foreground, bg-primary
  • No raw colors like bg-white
  • Dark mode — Both :root and .dark define same tokens in app/globals.css
  • Prefer flex and gap — No space-* classes
  • Accessibility — Semantic landmarks, labels, alt text
  • UI copy is Bengali — Product data stays as entered (English)
  • Use formatTaka for prices (৳)
  • Use formatDate with Bengali month names
  • Shop details live only in lib/shop-config.ts
